Logic Explanation - Phase 3

Persistent State: Your loot now survives page reloads! We save everything to localStorage using JSON.stringify() and load it back with JSON.parse(). The app auto-saves after every change.

State Lifecycle: The app follows a clear pattern: when you add/remove loot or change party size, we save to localStorage first, then update the UI. When the page loads, we restore from storage first, then update the UI. This keeps everything in sync.

Reset Functionality: The new "Reset All" button lets you start fresh - it clears the loot array, resets party size to 1, and wipes the saved data from localStorage. No page refresh needed!

Data Validation: When restoring saved data, we carefully check each loot item to make sure it's still valid. If something's corrupted (like negative values or missing names), we skip just that item instead of crashing. The valid items still load fine.

Single Source of Truth: Even with persistence, lootArray and partySize remain the only things that matter. localStorage is just a backup - the UI never reads directly from it. updateUI() still handles all rendering and calculations.

Debugging: During development, we set breakpoints in the restoration process to verify that data loads correctly before rendering. This helped confirm the lifecycle works as intended.
